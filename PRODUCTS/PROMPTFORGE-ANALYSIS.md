# ניתוח PromptForge → מה לשאוב ואיזה מוצר להכין 🧰

> נסקר **`promptforge.click`** (2026-08-07): ספריית פרומפטים מובנים למפתחים. מכירה **חד-פעמית ~$15** (בלי מנוי), 13 קטגוריות (frontend/backend/mobile/DevOps/security/game…), תמיכת MCP, "SaaS kit". תאריך: 2026-08-07.

## 1. מה לשאוב (3 דברים)

### א. פורמט הפרומפט המובנה — לאמץ פנימית בכל HELIX ✅ (הכי בעל-ערך)
המבנה שלהם: **role מומחה + inputs בסוגריים מרובעים + workflow ממוספר + hard constraints + output contract**. זה בדיוק מה שהופך פרומפט מ"בקשה" ל"מפרט". **לאמץ כסטנדרט** ל:
- **prompt panel של Rank** (מוצר 4) — כל ניתוח GSC/GEO כפרומפט מובנה עם output contract.
- **סקילים** (baldiga, geo-content-strategist, SDR outreach) — output contract מונע drift.
- מנוע התוכן — כבר משתמש בזה חלקית (`{"intent":"","title":""...}`); להרחיב לכל הסקילים.

### ב. מודל המונטיזציה — lead magnet זול 💰
$15 one-time, גישה קבועה, בלי מנוי = **top-of-funnel**. לא רווח מרכזי — **דלת כניסה** לאקו-סיסטם. אותה מכניקה כמו score-as-lead-magnet של [[barbot-review]].

### ג. הטקסונומיה — 13 אוספים לפי תחום
רעיון האריזה: pack per-נישה. אצלנו → pack per-מוצר או per-מחלקה.

## 2. הבעיה עם המוצר שלהם (ה-white-space שלנו)
- **מפתחים + אנגלית** — שוק רווי (יש עשרות ספריות פרומפטים חינמיות; המחיר רץ ל-0).
- פרומפט הוא **קומודיטי** — אפשר להעתיק, ChatGPT מייצר אותו. מכירת פרומפטים = מרוץ לתחתית.
- **המסקנה:** אל תמכור פרומפטים. תמכור את מה שהם *מייצרים*.

## 3. שני מוצרים אפשריים

### מוצר A — "HELIX Prompts" (lead magnet, build קטן) 🟢
ספריית פרומפטים **בעברית, לעסקים (לא מפתחים)**: שיווק/מכירות/HR/שירות/משפטי — מובנים בפורמט של §1א. חינם או ~₪49, כ-**דלת כניסה** לאקו-סיסטם HELIX. בידול: עברית + עסקי + לא-דבלופר.
- **סיכון:** קומודיטי. ערך אמיתי רק כ-funnel, לא כמוצר-רווח.

### מוצר B — "Prompt-to-Product" / אשף אריזה (ה-play החזק) 🔴
במקום למכור פרומפט, המשתמש מתאר צורך → HELIX **מריץ** את הפרומפט המובנה ומחזיר **תוצר מוכן** (מאמר / דף נחיתה / רצף מיילים / קמפיין). PromptForge מוכר את המתכון; **HELIX מוכר את הארוחה.**
- זה בעצם **כבר ה-DNA של HELIX** — כל מוצר הוא "prompt מובנה עטוף ב-UI". הלקח מ-PromptForge: **לתעד את ה-prompt-structure כנכס פנימי** (ספריית פרומפטים-אב שכל המוצרים מושכים ממנה), עם versioning ו-A/B.
- **המלצה:** לבנות **`@helix/prompts`** — מודול משותף (כמו `@helix/channels`) של פרומפטים-אב מובנים, ש-Rank/SDR/OPS/Guard כולם צורכים. משפר עקביות איכות חוצה-מוצר.

## 4. המלצה
1. **מיידי (זול, ערך גבוה):** לאמץ את פורמט §1א ולבנות מודול `@helix/prompts` משותף. משפר את *כל* המוצרים הקיימים.
2. **אופציונלי (funnel):** "HELIX Prompts" בעברית כ-lead magnet ל-STAGE.
3. **לא לבנות** מוצר מכירת-פרומפטים עצמאי — קומודיטי, מרוץ ל-0.

> **בשורה אחת:** PromptForge שווה בתור **תבנית-מבנה ומודל-funnel**, לא בתור מוצר להעתיק. השאיבה האמיתית = מודול פרומפטים-אב משותף (`@helix/prompts`) שמשדרג את כל האקו-סיסטם.
