# מוצר 9: HELIX Guard — סורק אבטחה + נגישות + פרטיות ל-vibecoders 🛡️🇮🇱

> **בדיקת אבטחה, נגישות (ת"י 5568) ופרטיות אוטומטית לאפליקציות שנבנו עם AI** — דוח דו-לשוני עברית/אנגלית, ציון לכל עמוד, ותיקונים מוכנים להדבקה.
> נבנה על מנוע **ClaudeGuard-IL** (`github.com/Freespirits/claudeguard-il`, zero-deps, MIT). תאריך: 2026-08-07 · סטטוס: אפיון.

## 0. מאיפה זה בא (הוכחה חיה — מצאנו **וגם תיקנו**)
הרצנו את מנוע ClaudeGuard על **אפליקציית PLUG שלנו** (768 קבצים, כיסוי 100%). התוצאה: 507 ממצאים, 18 P0 "confirmed". אחרי **אימות ידני**: 2 false-positive · 4 מכוונים-ותקינים · **12 חורים אמיתיים** — כולל 2 כספיים (`payment_link_transactions`, `affiliate_conversions` — הזרקת תשלומים/המרות מזויפות). **כולם תוקנו** (2026-08-08) במיגרציית `20260808000000_rls_hardening.sql` + תיקוני מקור ב-`groop_features.sql`, נדחף ל-main. זה **בדיוק** לולאת הערך של Guard: סרוק → אמת → תקן → הוכח. אם זה קרה לנו — זה קורה לכל vibecoder. (דוח: `plug/security/claudeguard-scan-2026-08-07.md`.) **הלקח למוצר:** האימות-הידני קריטי — הכלי לבדו נותן verdict "critical" עם 18 P0, אבל האמת היא 12. **HELIX Guard חייב שכבת אימות** (human/AI) מעל המנוע הגולמי, אחרת מוכר פאניקה.

## 1. האבחנה — למה עכשיו
- **כולם מקודדים עם AI** (Lovable / Bolt / v0 / Cursor / Claude Code). המהירות גבוהה, הבדיקה — אפס. Supabase/Firebase נפתחים בלי RLS, secrets נחשפים, IDOR בכל route.
- **נגישות = חובה חוקית בישראל** (ת"י 5568 / WCAG 2.0 AA). אתר ללא נגישות = **חשיפה לתביעה** (ותביעות נגישות נפוצות בישראל). זה לא "nice to have" — זה **קנס**.
- **פרטיות** — חוק הגנת הפרטיות המעודכן (2024) מחייב מידע-אבטחה. עוד שכבת חשיפה.
- אף כלי גלובלי (Snyk/Semgrep) לא נותן את השילוב **אבטחה + ת"י-5568 + עברית** לשוק ה-SMB הישראלי.

## 2. הבידול (מה שאף אחד לא נותן ביחד)
1. **שלושה עמודים בדוח אחד:** אבטחה · נגישות (ת"י 5568) · פרטיות — כל אחד מדורג בנפרד.
2. **עברית-native + חוק ישראלי** — schema ישראלי, שעות שבת, ת"י 5568 בעברית. Snyk לא יודע מה זה.
3. **מודל כנות (ה-moat התרבותי, כמו seo-god):** "סריקה נקייה אינה הוכחה לבטיחות." הכלי מפריד בין `confirmed` ל-`needs-review`, מתעד ERRATA, ולא מנפח P0. **בונה אמון** מול לקוח ששרוף מ-false-positives של סורקים.
3. **תיקונים מוכנים להדבקה** — לא רק "יש בעיה" אלא ה-SQL/קוד לתקן (guard-recipes).
4. **אקו-סיסטם HELIX** — יושב על אותו Supabase/edge, ומשלים את מוצר 5 (Shield/מוניטין): Guard = הצד הטכני, Shield = הצד המוניטין.

## 3. מה המערכת עושה
- **Tier 0 (סטטי, ברירת מחדל):** קורא קוד/קונפיג/תלויות/כללי RLS/manifests → ממצאים מדורגים עם evidence + תרחיש-תקיפה + תיקון.
- **Tier 1 (passive live):** TLS, headers, cookies, קבצים חשופים על URL חי.
- **Tier 2 (active probes):** 4 בדיקות-עשן (reflected markup, quote injection, open redirect, CSP) — **דורש אישור-בכתב + הצהרת-בעלות** (allowlist, rate-limit, dry-run).
- **ציות:** נגישות (alt, labels, ניווט-מקלדת, `html lang`, וידאו) + פרטיות (cleartext, session-cookie flags).
- **פלט:** דוח דו-לשוני + **SARIF 2.1** ל-GitHub Code Scanning.

## 4. מודל הכנסה (לפי HELIX Pricing Master, 3 מדרגות ערך)
| מסלול | מה כולל | קהל |
|---|---|---|
| **Scan** (חד-פעמי / freemium) | סריקת Tier 0 + דוח + ציון → **lead magnet**. "כמה מסוכן האתר שלך?" | כל vibecoder — top-of-funnel |
| **Monitor** (מנוי חודשי) | GitHub App — סריקה **בכל push/deploy** + gate ב-CI + התראות | עסק עם אתר חי |
| **Certified** (שנתי) | תעודת "HELIX Guard Certified" + badge אמון לאתר + סריקת נגישות תקופתית לצרכי **עמידה בחוק** | עסקים שצריכים כיסוי משפטי |

- **ה-wedge שממיר:** freemium scan מחזיר ציון + 3 חורים אמיתיים → פחד → מנוי. (אותה מכניקה של BarBot Profile-Score → [[barbot-review]].)
- **ה-badge = viral loop:** "HELIX Guard Certified" על אתרי לקוחות = חשיפה חינם.

## 5. GTM ואקו-סיסטם
1. **HELIX STAGE (ערוץ ההפצה העיקרי) — Guard נפתח רק לאחר החיבור למערכת.** ✅ **נבנה 2026-08-08:**
   - **דף הנחיתה "בדיקת המיזם"** (`helix/app/startups/readiness`) — Guard מופיע כ-unlock עתידי (פריט GET #07): "סריקת אבטחה + נגישות מעמיקה — 🔓 נפתח לאחר החיבור ל-STAGE". טופ-אוף-פאנל, לפני החיבור.
   - **דשבורד STAGE** (`helix-stage/.../dashboard`) — כרטיס Guard מוצג **אחרי login** (=post-connection), CTA "הצטרפו לרשימה" (בקרוב). זה מממש את "רק לאחר החיבור למערכת".
   - הזרימה: readiness scan (חינם, בלי הרשמה) → חיבור ל-STAGE → Guard נפתח בדשבורד → סריקה + badge.
2. **HELIX Rank** — לקוח SEO שכבר משלם → up-sell ל-Guard ("קידמנו אותך, עכשיו בוא נאבטח").
3. **cross-sell עם Shield (מוצר 5):** ממצא אבטחה → משימת מוניטין; דוח מאוחד ב-Reports (מוצר 2).
4. **זווית סוכנויות:** סוכנות שבונה אתרים ב-Lovable → Guard כ-line-item לכל לקוח (white-label בהמשך).

## 6. סיכונים
- **אחריות משפטית:** דוח "נקי" שאחריו פריצה. **ההגנה = מודל הכנות** — לעולם לא לומר "בטוח", תמיד "לא הוכח כלום". חוזה עם disclaimer.
- **Active probes = משטח משפטי/אתי.** להישאר ב-Tier 0/1 כברירת מחדל; Tier 2 רק עם אישור-בכתב + allowlist (הכלי כבר אוכף את זה).
- **false-positives** → שוחקים אמון. המנוע כבר מפריד confirmed/needs-review; לחשוף רק confirmed כברירת מחדל.
- **תלות במנוע צד-ג' (MIT):** fork פנימי, כמו שעשינו ל-fire-enrich ב-SDR.
