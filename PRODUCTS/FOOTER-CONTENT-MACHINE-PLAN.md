# HELIX — תוכנית "מכונת התוכן והפוטר"

**מבוסס על teardown מלא של Outloop.co (כל ~40 דפי הפוטר + 22 מאמרי Learn).**
נכתב: 2026-08-19. סטטוס: תוכנית מאושרת לביצוע, גל 1 ראשון.

---

## 0. הרעיון בשורה אחת

הפוטר של Outloop הוא לא ניווט — הוא **מכונת SEO/GEO + לידים** בנויה מ-7 סוגי נכסים חוזרים.
אנחנו משכפלים את המכונה ל-HELIX (עברית, סוכנויות/שיווק/מכירות בישראל), ממונפים על מנוע Rank ו-17 המאמרים הקיימים.

**למה זה עובד אצלם:** hub-and-spoke הדוק שבו כל עמוד תופס keyword אחד, מקשר לשאר, וכולם מנקזים לאותו CTA. הם גם **המציאו קטגוריה** ("credential broker", "loop engineering") ומדרגים עליה בלי תחרות.

## 2. 7 הטריקים שמשכפלים (חובה בכל נכס)

1. **שלד מאמר קבוע:** TL;DR ("בקצרה") → הכאב → הדרך הישנה/המסוכנת → פתרון HELIX → **FAQ עם schema** → CTA.
2. **המצאת קטגוריה/מונח בעברית** — לתפוס keyword בלי תחרות (ראה §5).
3. **נוסחה זכירה בראש** שחוזרת בדיאגרמה וב-FAQ (כמו "Risk = exposure × iterations").
4. **דיאגרמת-חתימה אחת** חוזרת בכל המאמרים — נכס אמון ויזואלי אחיד.
5. **שקיפות שמבדלת** — סעיף "מה אנחנו *לא* פותרים" / trade-off כן. בונה אמון.
6. **עמוד סטטיסטיקות מתוארך** — כל stat עם מקור+תאריך+לינק. מגנט-לינקים + ציטוט ב-AI (GEO).
7. **CTA כהצהרת-בעיה** — לא "הירשם" אלא "מוכן להפסיק ל___?" (מנסח מחדש את הכאב).

**בונוס — טריק הפרסונות:** דף use-case = תבנית אחת, מחליפים רק Hero + pain-points לכל פרסונה. דף לכל וורטיקל בזול.

## 3. התבניות (Templates) — לכתוב פעם אחת

### תבנית A — מאמר Spoke (long-tail, ~1,200-1,400 מילים)
```
H1: [keyword מדויק בעברית]
בקצרה: (2-3 שורות TL;DR)
H2: הבעיה — [הכאב של הפרסונה]
H2: למה הדרך הרגילה נכשלת — [הדרך הישנה]
H2: הגישה של HELIX — [הפתרון] + דיאגרמת-חתימה
H2: איך זה עובד — [3-5 שלבים ממוספרים]
H2: שאלות נפוצות — [4-8 שאלות = שאילתות-כלי ממש] + FAQ schema
CTA: "מוכן ל___?" → התחל / קבע שיחה
```

### תבנית B — עמוד Pillar (מונח-על, 2,800-4,000 מילים)
זהה ל-A אך: הגדרה מלאה של המונח + **טבלת השוואה** (HELIX מול קטגוריות סמוכות) + מסגרת רעיונית (כמו "5 שכבות") + קישור ל-8-10 spokes.

### תבנית C — Use-case לפי פרסונה
```
Hero: [כאב הפרסונה כותרת] · Pain-points (3-6) · איך זה עובד (5 שלבים, זהה בכל הדפים) · Features · CTA
```
משכפלים לכל וורטיקל: מחליפים רק Hero + Pain-points.

### תבנית D — Compare
```
"HELIX הוא לא ___" (הגדרת קטגוריה) → טבלת ✓/— → סעיף trade-off כן → FAQ → CTA
3 סוגים: מול מתחרה · מול "לעשות לבד" · מול "לשכור עובד"
```

## 4. תוכנית הגלים

### גל 1 — Learn Hub (ROI מקסימלי, ממנף קיים)
1. **בונים את תבנית A + B** (קומפוננטה + FAQ-schema + דיאגרמת-חתימה + CTA-כהצהרת-בעיה) — פעם אחת.
2. **ממירים 17 מאמרים קיימים** למבנה hub עם קבוצות-נושא.
3. **מוצר-דגל ראשון = Rank** (מנוע SEO/GEO כבר שם): pillar אחד + 3-4 spokes.
4. **עמוד סטטיסטיקות** מתוארך (מגנט GEO).

### גל 2 — נכסי לידים
- **Free Playbook** — "המדריך התפעולי לצוות שיווק/מכירות עם סוכני AI" + workflows מוכנים, הורדה בלי אימייל.
- **קטלוג יכולות** — עמוד מרוכז "מה צוותי הסוכנים של HELIX יודעים לעשות" + סטטוסי זמינות.
- **Compare pages** (תבנית D) — מול מתחרה מרכזי + מול לעשות לבד + מול לשכור עובד.
- **Use-case per persona** (תבנית C) — דף לכל וורטיקל.

### גל 3 — העמקה
- **מחשבון ROI** אינטראקטיבי (עלות סוכן HELIX מול שכר עובד).
- **עמוד אמון/אבטחה** בשקיפות רדיקלית.
- **מניפסט** ("מוצרים = צוותי סוכנים" — הנרטיב כבר קיים).
- **תוכנית שותפים/מיישמים** (משפך 5 שלבים).

## 5. אסטרטגיית קטגוריה — מונחים להמציא בעברית

כמו ש-Outloop המציאו "credential broker" / "loop engineering", HELIX צריכה לתפוס מונחים בלי תחרות. מועמדים (הנרטיב כבר קיים):
- **"צוות סוכנים"** / **"סוכן-מחלקה"** — כל מוצר = מחלקה של סוכנים.
- **"אוטונומיה מבוקרת"** — ה-autonomy switch (advisor→approve→autopilot).
- **"מנוע [X]"** לכל מוצר.

לכל מונח: עמוד pillar "מה זה ___" שמגדיר את הבעיה במונחים שלנו.
